## Архитектура

```
database.xlsx  ──[update_data.py + DeepL]──>  data.js  ──>  cheatsheet.html
   (источник)         (конвертер)              (готовый)    + trainer.html
```

**Один источник правды — `database.xlsx`.**
Все правки контента — в xlsx, потом запуск конвертера, потом коммит.

UI-текст (кнопки, заголовки) — отдельно, в `i18n/*.js`, не связан с xlsx/data.js (см. «Мультиязычность» ниже).

## Как добавить слово / правило / тест

1. Открыть `database.xlsx` (Excel или LibreOffice)
2. Перейти на нужный лист (nouns, verbs, adjectives, adverbs, pronouns, numbers, phrases, sounds, terms, rules, questions)
3. Добавить строку (id можно не заполнять — сгенерируется автоматически)
4. Сохранить xlsx
5. В терминале из корня репо: `python update_data.py`

> Перед первым запуском: `pip install -r requirements.txt` (нужен только `openpyxl`).
> Если настроен DeepL-ключ — заодно переведётся на EN всё новое/изменённое (см. «Мультиязычность»).

6. `git add . && git commit -m "..." && git push`

> Изменения появляются на сайте только после пуша. Локально сайт работает оффлайн — двойной клик по `index.html`.

### Флаг «новое» (`new`) и отчёт в консоли

Колонка `new` есть на всех контентных листах (nouns, verbs, adjectives, adverbs, phrases,
pronouns, numbers, terms, sounds, rules). Три состояния:

| Значение в ячейке | Смысл | На сайте | В отчёте `update_data.py` |
|---|---|---|---|
| пусто / `FALSE` / `0` / `no` / `нет` | обычная запись | — | не показывается |
| `TRUE` / `1` / `x` / `yes` / `да` | новая запись | попадает в буфер «Neu» | без метки |
| `Update` / `upd` / `u` / `обновлено` | отредактировал существующую | тоже попадает в буфер «Neu» (как `TRUE`) | помечена `↻ aktualisiert` |

Регистр не важен. После `python update_data.py` в консоли печатается сводка по всем строкам
с непустым `new` — текущее состояние xlsx на момент запуска, а не диф с прошлым прогоном:

```
+53 neue Wörter (davon 2 aktualisiert):
  · 35 Nomen
  · 6 Verben
  · 9 Adjektive
  · 2 Adverbien
  · 1 Begriff

+3 neue Regeln:
   • Komposita — сложные слова (Wort 1 + Wort 2 = Wort 3)
   • Genitiv Singular — образование и употребление ↻ aktualisiert
```

Флаг сам не сбрасывается — сними галочку в xlsx вручную, когда запись больше не нужно
показывать в сводке и в буфере «Neu» на сайте.

## Версионирование и кеш

Все статические ассеты (`theme.css`, `data.js`, `i18n/ru.js`, `i18n/en.js`, `i18n/i18n.js`)
версионируются одной общей датой — единый источник правды это маркер в самом верху
`<head>` в `index.html`:

```html
<!-- CACHE_VERSION: 20260803 -->
```

**Меняешь дату только в этой одной строке.** Pre-commit hook (`.git/hooks/pre-commit`) при
коммите, затрагивающем любой из ассетов:

1. Проверяет, что дата в маркере — сегодняшняя (иначе блокирует коммит с подсказкой).
2. Сам прописывает это значение во **все** `?v=...` у этих файлов во **всех** html-файлах
   (`index.html`, `about.html`, `faq.html`, `cheatsheet.html`, `trainer.html`).
3. Добавляет изменённые файлы в тот же коммит.

Руками бампать версию где-либо, кроме маркера в `index.html`, не нужно — и даже если
где-то она случайно разъедется, хук сам выровняет её при следующем коммите.

## Мультиязычность (RU/EN)

Два независимых слоя — сами немецкие слова не переводятся, только русскоязычная обвязка.

**Слой 1 — UI-текст.** Кнопки, заголовки, статичные подписи — в `i18n/ru.js` и `i18n/en.js`
(плоский объект `ключ: строка`, значения могут содержать HTML: `<br>`, `<strong>`, `<a>`).
Подключены через `i18n/i18n.js` — переключатель RU/EN в шапке (кнопка рядом с темой), выбор
хранится в `localStorage`, без сетевых запросов. Разметка: `data-i18n="key"` (innerHTML),
`data-i18n-title="key"` (атрибут title), `data-i18n-aria="key"` (aria-label),
`data-i18n-placeholder="key"` (placeholder). Новую строку — просто добавь такой же ключ в оба файла.

Подключено на `index.html`, `about.html`, `faq.html`, `cheatsheet.html`, `trainer.html`
(React — свой хук `useLang()`, читает `t()`/`getLang()` из `i18n/i18n.js` напрямую в JSX,
без `data-i18n`-разметки). Переведена вся UI-шелуха (экраны, кнопки, карточки, тесты,
результаты) — **кроме самих текстов тестовых вопросов** (генерируются шаблонами в
JS-коде трейнера), они пока только на русском — отдельная, более рискованная задача на будущее.

**Слой 2 — переводы контента в `data.js`.** `update_data.py` при каждом запуске сверяет
русскоязычные поля с предыдущим `data.js`: если значение новое или изменилось — переводит
через DeepL API и кладёт результат рядом, в поле с суффиксом `En`. Если не менялось — берёт
готовый перевод из старого `data.js`, к API не обращается (лишний трафик и лимит не тратятся).

Переводится:
- `VOCAB`: `ru` → `en`, `note` → `noteEn`, `altRu` → `altEn`, `exampleRu` → `exampleEn`, `warning` → `warningEn`
- `RULES`: `title` → `titleEn`, `content_md` → `content_md_en` (markdown-разметка `**bold**`,
  таблицы `|`, немецкие примеры — сохраняются, переводится только русский текст), `note` → `noteEn`
- `TERMS`: `ru` → `en`, `note` → `noteEn`
- `CONJUGATIONS`, `REGEL_VERBS`: `ru` → `en`
- `SOUNDS`: `pronunciation` → `pronunciationEn` (кириллическая фонетическая транскрипция → латинская)

`cheatsheet.html` показывает `*En`-поля вместо `ru`/`note`/... когда выбран EN (с фоллбэком на
русский, если перевода ещё нет — например, поле только что добавили в xlsx, а `update_data.py`
без DeepL-ключа ещё не запускали). `trainer.html` эти поля пока не читает.

`QUESTIONS` (банк вопросов тренажёра) пока не переводится — актуально только когда дойдём до
мультиязычности `trainer.html`.

Нужен ключ DeepL (бесплатный тариф хватает с большим запасом на разовый батч из ~1500 слов):

1. Зарегистрироваться на [deepl.com/pro-api](https://www.deepl.com/pro-api) → **DeepL API Free**
   (карта нужна для верификации, списаний в рамках бесплатного лимита не будет)
2. В личном кабинете → **Account** → скопировать **Authentication Key** (заканчивается на `:fx`)
3. В корне репозитория создать `.env` (уже в `.gitignore`, в git не попадёт):
   ```
   DEEPL_API_KEY=твой-ключ:fx
   ```
4. `pip install python-dotenv` (опционально — без него ключ можно передать через переменную
   окружения напрямую: `DEEPL_API_KEY=... python update_data.py`)
5. Обычный `python update_data.py` — перевод новых/изменённых значений подхватится сам

Без `.env`/ключа скрипт работает как раньше, просто без EN-полей — в предупреждениях в конце
будет строка `DEEPL_API_KEY не задан — перевод en пропущен`, это не ошибка.

## Telegram-бот «Слово дня»

Отдельный подпроект в `telegram-bot/` — раз в день постит в канал слово из `data.js` в виде
квиза с кнопками-вариантами (дистракторы подбираются тем же каскадом «тема → похоже по

Не часть сайта, не задействует GitHub Pages — свой Python-скрипт, свои зависимости, свой
README с инструкцией по запуску: [`telegram-bot/README.md`](telegram-bot/README.md).

## Как добавить запись в changelog

Открыть `changelog.js`, вставить новый объект в **начало** массива:

```js
window.CHANGELOG = [
  {
    "date": "2026-06-01",
    "title": "Название обновления:",
    "items": [
      "Что добавлено / исправлено"
    ]
  },
  ...
];
```

Дата в формате `YYYY-MM-DD`. Хранятся последние 10 записей.

## Установка и запуск (с нуля)

Если ты только что склонировал репо или сел за новый комп — вот что нужно сделать.

### 1. Что должно быть установлено

- **Python 3.10+** — для конвертера `update_data.py` (проверка: `python --version`)
- **Git** — для коммитов и пуша (проверка: `git --version`)
- **Браузер** — любой современный (Chrome, Firefox, Edge, Safari)

> Excel / LibreOffice — только если планируешь редактировать `database.xlsx`. Само приложение работает без них.

### 2. Клонировать репо

```bash
git clone https://github.com/R4-studio/deutsch-tools.git
cd deutsch-tools
```

### 3. Поставить Python-зависимости

Только если планируешь обновлять `data.js` (для просмотра/тестов — не нужно).

```bash
pip install -r requirements.txt
```

Внутри `openpyxl` (обязателен) и `python-dotenv` (опционален, нужен только для EN-перевода через DeepL — см. «Мультиязычность»).

### 4. Включить pre-commit хук (опционально, но рекомендуется)

Хук блокирует коммит, если обновил `data.js`/`theme.css`, но забыл бампнуть `?v=` в html-файлах.

```bash
cp pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

### 5. Открыть сайт локально

Просто двойной клик по `index.html`. Работает оффлайн, без сервера, без билда.

### 6. Типичный цикл правки

```
[правка database.xlsx]
       ↓
python update_data.py         ← заодно переведёт новое на EN, если есть DEEPL_API_KEY
       ↓
[проверить локально — двойной клик index.html]
       ↓
git add . && git commit -m "..."   ← хук проверит ?v= автоматом
       ↓
git push                            ← на сайте обновится через ~1 мин
```
