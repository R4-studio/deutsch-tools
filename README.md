# Deutsch Tools

Справочник и тренажёр по немецкому языку (A1 → B1).

🌐 [r4-studio.github.io/deutsch-tools](https://r4-studio.github.io/deutsch-tools)

Сейчас в базе: **2554 слова**, **67 правил**, 233 ручных тестовых вопроса, 59 терминов, 17 звуковых сочетаний, 174 таблицы спряжения нерегулярных глаголов, 130 тем. Интерфейс и контент — на двух языках, RU и EN.

## Архитектура

```
database.xlsx  ──[update_data.py + DeepL]──>  data.js  ──>  cheatsheet.html
   (источник)         (конвертер)              (готовый)    + trainer.html
                            ↑                                     ↑
                   docs/en-fix/*.json                     rule-render.js
                (ручные правки перевода)              (общий рендер правил)
```

**Один источник правды — `database.xlsx`.**
Все правки контента — в xlsx, потом запуск конвертера, потом коммит.

UI-текст (кнопки, заголовки) — отдельно, в `i18n/*.js`, не связан с xlsx/data.js (см. «Мультиязычность» ниже).

## Листы в `database.xlsx`

`Settings-XLSX`, `nouns`, `verbs`, `adjectives`, `adverbs`, `phrases`, `pronouns`, `numbers`, `terms`, `sounds`, `rules`, `questions`.

### Новая тема заводится в двух местах

`Settings-XLSX` — мастер-список допустимых пар `domen:group` по каждому листу. Но одной записи там мало: подпись темы берётся из `GERMAN_LABELS` / `RUSSIAN_LABELS` внутри `update_data.py`.

- **нет пары в `Settings-XLSX`** → конвертер ругается предупреждением
- **нет подписи в `*_LABELS`** → конвертер молчит, а тема на сайте рисуется сырым ключом вида `society:ecology`

Второе не ловится проверкой, поэтому заводить надо сразу оба. Иконка в `GERMAN_LABELS` берётся из `ICON_LIBRARY` — 106 SVG, выгружаются в `data.js` целиком как `ICON_SVGS`.

### Колонки, о которых стоит знать

| колонка | лист | смысл |
|---|---|---|
| `alt-de` / `alt-ru` | словарные | вторая форма и второй перевод. Не пихать второй перевод в `note` |
| `no_ru_forms` | verbs | глагол не спрягается по-русски (`es geht`, безличные). Такие исключаются из заданий тренажёра и из предупреждений конвертера |
| `examples` | rules | примеры к правилу, построчно `немецкое – перевод`. Рендерятся отдельным блоком в карточке |
| `rule` | questions | привязка вопроса к правилу (`r0053`). Вопрос попадает в тест этого правила в режиме «Правила» |
| `difficulty` | questions | сложность 1–5 вручную. Пустая ячейка — подставляется дефолт по типу вопроса |
| `context` | phrases | пометка вида `Redemittel` — речевое клише, а не обычная фраза |
| `note` | все | пояснение, а не второй перевод. Если внутри стоит id другого правила (`r0015`), в карточке появится ссылка «см. также» — сразу на все упомянутые |
| `new` | все контентные | см. ниже |

## Как добавить слово / правило / тест

1. Открыть `database.xlsx` (Excel или LibreOffice)
2. Перейти на нужный лист
3. Добавить строку (id можно не заполнять — сгенерируется автоматически)
4. Сохранить xlsx
5. В терминале из корня репо: `python update_data.py`

> Перед первым запуском: `pip install -r requirements.txt`.
> Если настроен DeepL-ключ — заодно переведётся на EN всё новое/изменённое (см. «Мультиязычность»).

6. `git add . && git commit -m "..." && git push`

> Изменения появляются на сайте только после пуша. Локально сайт работает оффлайн — двойной клик по `index.html`.

### Флаг «новое» (`new`) и отчёт в консоли

Колонка `new` есть на всех контентных листах. Три состояния:

| Значение в ячейке | Смысл | На сайте | В отчёте `update_data.py` |
|---|---|---|---|
| пусто / `FALSE` / `0` / `no` / `нет` | обычная запись | — | не показывается |
| `TRUE` / `1` / `x` / `yes` / `да` | новая запись | попадает в буфер «Neu» | без метки |
| `Update` / `upd` / `u` / `обновлено` | отредактировал существующую | тоже попадает в буфер «Neu» (как `TRUE`) | помечена `↻ aktualisiert` |

Регистр не важен. После `python update_data.py` в консоли печатается сводка по всем строкам
с непустым `new` — текущее состояние xlsx на момент запуска, а не диф с прошлым прогоном:

```
+53 neue Wörter (davon 2 aktualisiert):
  · 35 Nomen
  · 6 Verben
  · 9 Adjektive
  · 2 Adverbien
  · 1 Begriff

+3 neue Regeln:
   • Komposita — сложные слова (Wort 1 + Wort 2 = Wort 3)
   • Genitiv Singular — образование и употребление ↻ aktualisiert
```

Флаг сам не сбрасывается — сними галочку в xlsx вручную, когда запись больше не нужно
показывать в сводке и в буфере «Neu» на сайте.

Эта же сводка — готовая заготовка для поста в Telegram и записи в `changelog.js`.

## Версионирование и кеш

Единый источник правды — маркер в самом верху `<head>` в `index.html`:

```html
<!-- CACHE_VERSION: 20260918 -->
```

**Дата меняется только в этой одной строке.** Pre-commit hook (`.git/hooks/pre-commit`) при коммите, где затронут любой `.css` или `.js`:

1. Проверяет, что дата в маркере — сегодняшняя (иначе блокирует коммит с подсказкой).
2. Прописывает это значение во **все** `?v=...` у любых `.css` и `.js` во **всех** html-файлах репозитория.
3. Добавляет изменённые файлы в тот же коммит.

Хук работает по шаблону, а не по списку имён: **новый файл регистрировать не нужно**, он попадает под сброс кэша автоматически. Список html берётся из `git ls-files '*.html'`.

Единственное исключение — `changelog.js`: он подключается как `changelog.js?v=' + Date.now()`, то есть версионируется сам собой, и под шаблон не попадает (после `?v=` там кавычка, а не цифры). Правка ченджлога не требует бампать дату.

Руками бампать версию где-либо, кроме маркера в `index.html`, не нужно.

## Мультиязычность (RU/EN)

Три слоя — сами немецкие слова не переводятся, только русскоязычная обвязка.

**Слой 1 — UI-текст.** Кнопки, заголовки, статичные подписи — в `i18n/ru.js` и `i18n/en.js`
(плоский объект `ключ: строка`, значения могут содержать HTML: `<br>`, `<strong>`, `<a>`).
Подключены через `i18n/i18n.js` — переключатель RU/EN в шапке, выбор хранится в `localStorage`,
без сетевых запросов. Разметка: `data-i18n="key"` (innerHTML), `data-i18n-title`,
`data-i18n-aria`, `data-i18n-placeholder`. Новую строку — просто добавь такой же ключ в оба файла.

Подключено на всех страницах, включая `trainer.html` (React — свой хук `useLang()`, читает
`t()`/`getLang()` напрямую в JSX).

**Слой 2 — переводы контента.** `update_data.py` при каждом запуске сверяет русскоязычные поля
с кэшем в `translations.json` (ключ — хэш записи): если значение новое или изменилось, переводит
через DeepL и кладёт результат рядом, в поле с суффиксом `En`. Если не менялось — берёт готовый
перевод из кэша, к API не обращается.

Переводится:
- `VOCAB`: `ru` → `en`, `note` → `noteEn`, `altRu` → `altEn`, `exampleRu` → `exampleEn`, `warning` → `warningEn`
- `RULES`: `title` → `titleEn`, `content_md` → `content_md_en`, `examples` → `examplesEn`, `note` → `noteEn`
- `TERMS`: `ru` → `en`, `note` → `noteEn`
- `CONJUGATIONS`, `REGEL_VERBS`: `ru` → `en`
- `SOUNDS`: `pronunciation` → `pronunciationEn` (кириллическая транскрипция → латинская)

Английский считается **с немецкого напрямую**, а не с русского пересказа. Исключение — `altEn`:
если заполнено `alt-de`, перевод идёт `DE→EN`; если только `alt-ru`, идёт `RU→EN` и запись
помечается `altEnSource: "deepl-ru"`. Обратной проверки на этой ветке нет, поэтому разговорное
или образное слово в `alt-ru` приедет в английский буквально. Для таких случаев — слой 3.

Немецкие примеры, таблицы и markdown-разметка внутри правил при переводе сохраняются: переводится
только русский текст, число строк и количество `|` в каждой строке обязано совпадать с оригиналом.

> **Известная дыра: тесты только на русском, обе половины.**
>
> *Ручные вопросы из xlsx (233 шт.)* — секции `QUESTIONS` в `translations.json` нет вообще, английских
> полей у вопросов в `data.js` ноль. Тренажёр берёт `q.q`, `q.hint`, `q.explain` напрямую, без `wordField`.
>
> *Автогенерируемые* — собираются не из `window.t(...)`, а из русских строк прямо в коде: 32 литерала
> в блоке генераторов и поля `ru` в `PERSONAL_PRONOUNS_TABLE`, `POSSESSIVE_PRONOUNS_TABLE`,
> `TOPIC_RU_HINTS`. Вызовов `t()` внутри генераторов ноль.
>
> Это две разные задачи с общим симптомом. Обе в TODO.

**Слой 3 — ручные переопределения.** Файлы `docs/en-fix/*.json`. Структура: секция (`RULES`,
`VOCAB`, `TERMS`, `SOUNDS`) → id записи → поля с суффиксом `En` плюс `source: "manual"`.
Такая запись автопереводом не перезаписывается никогда. Правила подхватываются по маске
`translations-rules-batch*.json`, термины и звуки — из `translations-terms-sounds.json`.

Нужен ключ DeepL (бесплатного тарифа хватает с запасом):

1. Зарегистрироваться на [deepl.com/pro-api](https://www.deepl.com/pro-api) → **DeepL API Free**
2. **Account** → скопировать **Authentication Key** (заканчивается на `:fx`)
3. В корне репозитория создать `.env` (уже в `.gitignore`):
   ```
   DEEPL_API_KEY=твой-ключ:fx
   ```
4. Обычный `python update_data.py`

Без ключа скрипт работает как раньше, просто без EN-полей — в предупреждениях будет строка
`DEEPL_API_KEY не задан`, это не ошибка.

### Арбитр на Haiku

Если задан `ANTHROPIC_API_KEY`, спорные переводы догоняет второй проход. Логика такая: DeepL
перевёл `DE→EN`, затем результат переводится обратно `EN→DE`; если обратный перевод разошёлся
с оригиналом, запись помечается флагом. Флаги пачками уходят в Claude Haiku, который выносит
`ok` / `fix` / `skip`. Разобранное убирается из отчёта на ручной разбор, остальное остаётся
в `reports/en_review_vocab.md`. Сводка прогона — `reports/en_arbiter.md`.

Без ключа арбитр пропускается, все флаги остаются на ручной разбор.

## Режим «Правила» в тренажёре

Третий режим на главной тренажёра, рядом с «Учить» и «Тест».

- список всех правил по темам, у каждого — счётчик готовых вопросов;
- правило открывается, только если у него набрано **не меньше трёх** вопросов (`MIN_Q_FOR_TEST`
  в `rule-render.js`); остальные показаны приглушёнными с подписью «скоро»;
- клик по правилу сразу запускает тест по нему, без промежуточного экрана;
- внутри теста под карточкой вопроса — капсула «Посмотреть правило»: открывается оверлей
  с полным текстом, прогресс теста не сбрасывается;
- на карточке правила в справочнике — капсула «перейти к тесту», ведёт в `trainer.html?rule=rXXXX`;
- в разборе результатов каждый вопрос с заполненным `rule` ведёт к своей теории — во всех
  режимах, не только в «Правилах».

Вопрос попадает к пользователю двумя путями: через `rule` (режим «Правила») и через `topic`,
если тема входит в блок (обычные тесты по блокам). Ручные вопросы внутри уровня сложности
берутся раньше автогенерируемых.

## Как добавить запись в changelog

Открыть `changelog.js`, вставить новый объект в **начало** массива:

```js
window.CHANGELOG = [
  {
    "date": "2026-06-01",
    "title": "Название обновления",
    "items": ["Что добавлено / исправлено"],
    "titleEn": "Update title",
    "itemsEn": ["What was added / fixed"]
  },
  ...
];
```

Дата в формате `YYYY-MM-DD`. Хранятся последние 10 записей. Если английские поля не заполнить,
их переведёт `update_data.py`; ручной перевод помечается `manualEn: true` и не перезаписывается.

## Установка и запуск (с нуля)

### 1. Что должно быть установлено

- **Python 3.10+** — для конвертера `update_data.py` (проверка: `python --version`)
- **Git** — для коммитов и пуша (проверка: `git --version`)
- **Браузер** — любой современный

> Excel / LibreOffice — только если планируешь редактировать `database.xlsx`.

### 2. Клонировать репо

```bash
git clone https://github.com/R4-studio/deutsch-tools.git
cd deutsch-tools
```

### 3. Поставить Python-зависимости

```bash
pip install -r requirements.txt
```

Внутри `openpyxl`, `pymorphy3` и русские словари к нему. `python-dotenv` — опционально,
нужен только чтобы читать ключи из `.env`.

### 4. Включить pre-commit хук (рекомендуется)

```bash
cp pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

### 5. Открыть сайт локально

Двойной клик по `index.html`. React и Babel подгружаются с CDN — билда не нужно.

### 6. Типичный цикл правки

```
[правка database.xlsx]
       ↓
python update_data.py         ← заодно переведёт новое на EN, если есть DEEPL_API_KEY
       ↓
[проверить локально — двойной клик index.html]
       ↓
git add . && git commit -m "..."   ← хук проверит ?v= автоматом
       ↓
git push                            ← на сайте обновится через ~1 мин
```

### Проверка JSX без браузера

`trainer.html` компилируется Babel'ем прямо в браузере, поэтому синтаксическая ошибка в JSX
видна только в консоли. Чтобы поймать её сразу после правки:

```bash
node -e "
const fs=require('fs');
const s=fs.readFileSync('trainer.html','utf8');
const a=s.indexOf('<script type=\"text/babel\" data-presets=\"react\">');
fs.writeFileSync('/tmp/jsx-check.jsx', s.slice(s.indexOf('>',a)+1, s.indexOf('</script>', a)));
"
npx --yes -p @babel/core -p @babel/preset-react node -e "
require('@babel/core').transformSync(require('fs').readFileSync('/tmp/jsx-check.jsx','utf8'),
  {presets:['@babel/preset-react'],filename:'t.jsx'});
console.log('JSX ok');
"
```
